## Why it stalls: the same giv combination as func_800210B4

Every instruction is retail's except the packet-side registers and the two
words they cost, exactly func_800210B4's residue. `cc1 -dL` on this body:

```
Insn 152: giv reg 124 src reg 82 benefit 2 used 1 lifetime 1 replaceable mult 1 add 28
Insn 158: dest address src reg 82 benefit 2 used 1 lifetime 1 replaceable mult 1 add 7
giv at 158 combined with giv at 152
giv of insn 140 not worth while, 0 vs 72.
giv at 152 reduced to (reg:SI 143)
```

The code-byte store (`pkt+7`) is combined into the giv of `&pkt->r3`
(`pkt+0x1C`); every other packet giv is "not worth while" (benefit 2 minus
the add cost 2 is 0). So in this build `&pkt->r3` is reduced ONLY because
the store's benefit was added to it. Retail reduces the same `pkt+0x1C`
giv (`$t3`, used only by the last `swc2`) yet keeps `sb 7($a2)` on the biv,
so in retail that giv must have had a partner other than the store, and
the store must have been kept out of it.

Reading GCC 2.8.1's `combine_givs` (loop.c; the papermario 2.8.1 sources,
not our pinned binary): givs are walked in reverse insn order, and any
DEST_REG giv absorbs any later DEST_ADDR giv `express_from` can reach
(every MIPS reg+offset address costs 1), unless the address giv is already
`same` or `combined_with`. The only escapes in the source are a store whose
address is not a giv at all, or a store already combined into a giv that
is later ignored. No C spelling found here gives either. A DEST_ADDR giv
whose `validate_change` fails also keeps its old address, which is a third
route nobody has tried.

Tried in this round on this body: the link through a saved pointer
(`p = pkt; pkt++; ... link p`), 7/125 and worse (an `s0` spill). The
round-6 list in func_800210B4's report applies unchanged.

### Proposed learning

- **A loop giv is reduced only when it absorbs another**: alone, a
  `pkt+K` giv scores "0 vs N, not worth while" (benefit 2 minus add cost
  2). A reduced pointer next to unreduced siblings marks the giv that
  absorbed something; read `-dL` for which. (func_80021240)
