### Proposed learning

- The delay slots of this unit's "abs(x) > 700 || abs(z) > 700" sort

## Round 13 (charlie)

Two builds. The preserved round-9 body rebuilt at 120/138, `insertions 1
/ deletions 1`, as recorded.

- **The lever: abs as the ternary `x >= 0 ? x : -x`** (the unit's
  `absInt` helper, already used by func_8002CCEC, moved up above this
  function). 138/138, byte-exact, with the function back to `void`
  (the round-9 `s32` with no return is not needed).

Why: cc1 folds `x >= 0 ? x : -x` to an ABS rtx, emitted as the single
`abssi2` insn (`bgez x,1f; subu x,$0,x; 1:`; the local label is in the
template). `if (x < 0) x = -x;` (round 9's helper) expands to a real
conditional jump and a CODE_LABEL. reorg's `redundant_insn` scans back
from a branch only until a CODE_LABEL, so with the real label it could
not see that `$a0 = $s2` was already set (the 0x25 test's delay slot)
and that the first range test's slot had already set `$a2 = 2`; with
abssi2 it skips those insns in the target threads, which is retail's
`li a2, 2` slot, the bare `nop` slot and the near block without the
argument setup.

### Proposed learning

- **Delay slots after an `abs(x) > K` test that skip argument setup
  already done (target +8, a bare `nop`, a block missing its `move`/`li`):
  abs as `x >= 0 ? x : -x`**, which is the one-insn `abssi2`; `if (x <
  0) x = -x;` leaves a CODE_LABEL that stops reorg's redundancy scan.
  (func_8002A5B0)
