## The two levers

Both are needed; either alone leaves the round-6 residue.

1. **The code-byte store is `volatile`**, `((volatile POLY_xx *)pkt)->code =
   ...`. Loop still records it as an address giv and combines it into the
   last packet-address giv, whose benefit it supplies (alone, that giv is
   "not worth while": benefit 2 minus add cost 2). But loop runs with
   `init_recog_no_volatile()` (loop.c), so `validate_change` refuses to
   rebase a volatile memory reference onto the reduced pointer: the store
   keeps `7($a2)` on the biv while the giv it paid for is still reduced.
   That is exactly retail's `sb 7($a2)` beside a reduced last-colour/UV
   pointer. `*(volatile u8 *)&pkt->code` does NOT work: the front end folds
   `*&` and the volatile is lost (the `-dL` dump shows `mem/s`, not
   `mem/v`); that is why round 6's "volatile u8 store" failed.
2. **The packet pointer is a local copy of a `PACKET *` parameter.** With
   the parameter itself as the biv, its initial value is the incoming hard
   register (`bl->initial_value` is `$a2` when the biv's first set is the
   argument copy, loop.c `valid_initial_value_p`), so the reduced giv is
   initialised from `$a2`, takes `$a2`, and the biv is copied out (`move
   $t0, $a2`, the extra word). With a local, the initial value is the
   parameter's pseudo and the biv keeps `$a2`.

### Proposed learning

- **A store kept on the biv beside a reduced pointer it would have been
  folded into: a volatile store.** Loop cannot rebase a volatile reference
  (`validate_change` under `init_recog_no_volatile`), yet the giv still
  counts it. Spell it through a volatile-qualified struct pointer cast,
  `((volatile T *)p)->f = x;`; `*(volatile u8 *)&p->f` folds and loses the
  qualifier. (func_800210B4, func_80021240, func_80021434, func_8002097C)
- **A loop pointer copied out of its argument register at entry (`move
  $t0, $a2`) while a reduced giv takes `$a2`: the source looped on a local
  copy of the parameter**, `pkt = (POLY_G3 *)packet;`. (same functions)
