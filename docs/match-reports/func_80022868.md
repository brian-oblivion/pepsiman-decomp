# func_80022868 — MATCHED 80/80 (round 7, delta)

Unit `src/code_13068.c`. When game-state byte 0x3D3 is set, projects the
player's position (0x348 + 0x354 + `D_800A7308[0]`, `D_800AC858[0]`,
0x350 + 0x35C + `D_800A7308[2]`) through a fresh coordinate and draws
sprite 0x12D with `func_8001A3D4`, sized and coloured by how far 0x34C is
below its cap 0x3C0.

```c
void func_80022868(void) {
    GsCOORDINATE2 coord;
    MATRIX ls;
    SVECTOR size;
    s32 unused[2];
    CVECTOR color;
    s32 d;

    if (sGame.unk3D3 != 0) {
        GsInitCoordinate2(WORLD, &coord);
        coord.coord.t[0] = sGame.unk348 + sGame.unk354 + D_800A7308[0];
        coord.coord.t[1] = D_800AC858[0];
        coord.coord.t[2] = sGame.unk350 + sGame.unk35C + D_800A7308[2];
        GsGetLs(&coord, &ls);
        GsSetLsMatrix(&ls);
        d = (sGame.unk3C0 - sGame.unk34C) / 10;
        color.r = 2;
        size.vx = 100 - d;
        size.vy = size.vx / 2;
        color.g = color.b = color.cd = 0x40 - d;
        func_8001A3D4(0x12D, &size, &color, 2, &D_800ACEA8[D_80095750]);
    }
}
```

GameState gained `unk354`, `unk35C` and `unk3D3` (s8: retail reads it
with `lb`).

## Levers

- **Frame layout.** The first build put `color` at sp+0x90; retail has it
  at sp+0x98, with nothing stored at 0x90. An unused `s32 unused[2];`
  between `size` and `color` fixes it (the existing frame-gap learning,
  func_80023194). It adds a baselinable `-Wall` unused-variable warning.
- The three colour bytes stored 0x9B, 0x9A, 0x99 are the chained
  assignment `color.g = color.b = color.cd = v` (right to left).
- `color.r = 2` stored before `size` because it comes first in the source.
