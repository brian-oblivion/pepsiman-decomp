# func_8003FA88 — MATCHED (86/86), round 6, runner echo

Unit `src/code_29f54.c`. A 32-frame growing sprite step on a `Slot`
record: while the delay (`unk2`) is non-zero, count it down and return 0.
Otherwise set the local-screen matrix to (`x`, `y`, `z`) plus the record's
offset, draw sprite 0x11F at size `0x14 + frame` in colour
(1, c, c, c) with `c = 0x80 - frame * 4`, move the offset (`unkE -= 4`,
`unk10 += frame / 4`), advance the frame and return 1 when it reaches 0x20.

## The lever: the matrix set-up was an inline function

Round 5 parked func_8003F960 and func_8003FBE0 because retail rebuilds
`&coord` (`addiu aN, sp, 0x28`) and `&ls` (`addiu aN, sp, 0x78`) before
every call, while the build kept each in a saved register. Two clues
pointed at inlining: `coord`/`ls` sit after the caller's own `size` and
`color` in the frame (where an inline body's block is allocated), and
func_8003F8D4, right before these functions, is exactly that body.

- A `static __inline__` copy of func_8003F8D4's body, called with the sums,
  rematerialises both addresses as retail does (first build with it: the
  whole prologue and middle matched; only the tail differed). The inlined
  locals' addresses are never copied into a pseudo that CSE can share.
- A public `__inline__` on func_8003F8D4 itself works for the callers but
  moves func_8003F8D4's out-of-line copy to the end of the file (2.8.1
  defers public inlines to end of compilation): the whole image shifted.
- func_8003F8D4 rewritten as a call to the helper loses its own `s3` CSE of
  `&ls` (3 words short), so it keeps its own copy of the body.

## The tail

With a `ret` local and `if (p->unk2 != 0) {...; ret = 0;} else {...}`
(round 5's shape), everything matched but the return value: `ret` landed
in `a1`/`a2` with a `move v0` before `jr ra` (1 word long). Returning
directly from the `if (p->unk2 != 0)` arm moved the countdown to the end
of the function. `if (p->unk2 == 0) { ...; return ...; } p->unk2--;
return 0;` gives retail's layout (countdown as the fall-through, the
`move v0, zero` in the `j`'s delay slot) and the value straight in `v0`.
Then statement order: `unkE` before `unk10` (the reverse loads `unk10`
early). Writing `p->unk0++; return p->unk0 == 0x20;` matches too.

About 30 builds, no permuter.

### Proposed learning

- **A stack struct's address rebuilt (`addiu aN, sp, K`) before every call
  that takes it, with the struct after the caller's own locals in the
  frame: the code came from an inlined function.** Write a `static
  __inline__` helper; a non-inline spelling keeps the address in a saved
  register. A public inline is output at the end of the file, so an
  out-of-line twin keeps its own body. (func_8003FA88, func_8003F960,
  func_8003FBE0)
- **`if (!c) { ...; return x; } other; return 0;` puts `other` as the
  fall-through and the value straight into `v0`.** The if/else form with a
  `ret` local can leave `ret` in an argument register and add a `move v0`.
