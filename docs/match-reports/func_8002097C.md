# func_8002097C — MATCHED (166/166), round 7, runner charlie

Unit `src/code_a0bc.c`. The wireframe handler (row 7, column 0 of the handler
table, installed by func_80020C14's mode switch): each lit gouraud-textured
TMD quad becomes two 3-point gouraud polylines (LINE_G3, code 0x58, the
0x55555555 terminator in `pad`, length 7), (v0, v1, v3) and (v0, v2, v3),
the second sharing the first's end points and colours. Colours are lit with
`ncct` from a mid-grey (0x80) base; the fourth vertex is lit from normal 3,
not normal 2, as retail does. Both packets are linked at the quad's depth.
Needed `gte_ncct` and `gte_nccs` in `include/gte.h` (added).

```c
/** @brief A lit gouraud-textured TMD quad: a header, four UV words, then a
 *  normal index and a vertex index per corner. */
typedef struct {
    u32 hdr; /**< the TMD primitive header */
    u32 uv0; /**< u0, v0 and the CLUT */
    u32 uv1; /**< u1, v1 and the texture page */
    u32 uv2; /**< u2, v2 */
    u32 uv3; /**< u3, v3 */
    u16 n0;  /**< first normal index */
    u16 v0;  /**< first vertex index */
    u16 n1;  /**< second normal index */
    u16 v1;  /**< second vertex index */
    u16 n2;  /**< third normal index */
    u16 v2;  /**< third vertex index */
    u16 n3;  /**< fourth normal index */
    u16 v3;  /**< fourth vertex index */
} TmdGT4;

PACKET *func_8002097C(TmdGT4 *prim, SVECTOR *vtx, SVECTOR *nrm, PACKET *packet, s32 n, s32 shift,
                      GsOT *ot) {
    LINE_G3 *pkt;
    CVECTOR c;
    s32 v;
    s32 z;
    s32 i;
    u32 *tag;

    /* MATCHING: the packet pointer is a copy of the parameter, so the
     * loop starts its reduced pointer from it, not from $a3. */
    pkt = (LINE_G3 *)packet;

    for (i = 0; i < n; i++, prim++) {
        gte_ldv3(&vtx[prim->v0], &vtx[prim->v1], &vtx[prim->v3]);
        gte_rtpt();
        gte_stflg(&v);
        if (v & 0x7F85E000) {
            continue;
        }
        gte_nclip();
        gte_stopz(&v);
        if (v <= 0) {
            continue;
        }
        gte_stsxy3(&pkt[0].x0, &pkt[0].x1, &pkt[0].x2);
        *(u32 *)&pkt[1].x0 = *(u32 *)&pkt[0].x0;
        *(u32 *)&pkt[1].x2 = *(u32 *)&pkt[0].x2;
        gte_ldv0(&vtx[prim->v2]);
        gte_rtps();
        gte_stflg(&v);
        if (v & 0x7F85E000) {
            continue;
        }
        gte_stsxy2(&pkt[1].x1);
        gte_avsz4();
        gte_stotz(&v);
        c.r = 0x80;
        c.g = 0x80;
        c.b = 0x80;
        gte_ldrgb(&c);
        gte_ldv3(&nrm[prim->n0], &nrm[prim->n1], &nrm[prim->n3]);
        gte_ncct();
        gte_strgb3(&pkt[0].r0, &pkt[0].r1, &pkt[0].r2);
        *(u32 *)&pkt[1].r0 = *(u32 *)&pkt[0].r0;
        *(u32 *)&pkt[1].r2 = *(u32 *)&pkt[0].r2;
        gte_ldv0(&nrm[prim->n3]);
        gte_nccs();
        gte_strgb(&pkt[1].r1);
        /* MATCHING: volatile stores keep their own base; the order of the
         * index, read early, and the terminators is retail's schedule. */
        ((volatile LINE_G3 *)pkt)[0].code = 0x58;
        ((volatile LINE_G3 *)pkt)[1].code = 0x58;
        z = v >> shift;
        ((volatile LINE_G3 *)pkt)[0].pad = 0x55555555;
        ((volatile LINE_G3 *)pkt)[1].pad = 0x55555555;
        tag = (u32 *)ot->org + z;
        *(u32 *)pkt = (*tag & 0xFFFFFF) | 0x07000000;
        *tag = (u32)pkt & 0xFFFFFF;
        pkt++;
        tag = (u32 *)ot->org + (v >> shift);
        *(u32 *)pkt = (*tag & 0xFFFFFF) | 0x07000000;
        *tag = (u32)pkt & 0xFFFFFF;
        pkt++;
    }
    return (PACKET *)pkt;
}
```

## How it went

The first body had every instruction right except the base register of four
stores, the two code bytes and the two terminators: retail reduces a
`pkt+0x3C` giv (the second terminator's address), rebases the eight word
copies onto it (`lw -0x34($t0)` ...), yet leaves all four of those stores,
the terminator itself included, on the biv (`sw 0x3C($a3)`). Only a store
loop cannot rewrite does that, and loop runs `init_recog_no_volatile()`, so
`validate_change` refuses a volatile reference: the four stores are
volatile. That explained func_800210B4's two-round stall (its code byte is
the same store) and matched it and its two siblings the same session.

The second residue, the biv copied out of `$a3` while the reduced giv takes
`$a3`, is the giv's initial value: with the parameter as the biv it is the
incoming hard register (loop.c `valid_initial_value_p`); a local copy of a
`PACKET *` parameter makes it the parameter's pseudo.

The last two words were schedule: retail reads `v` between the code bytes
and the terminators, and `ot->org` after them. The volatile stores order
every other memory reference, so the source read `v >> shift` into a local
between them (`z`); the second link re-reads `v` (retail reloads it).

Ten builds.

### Proposed learning

- **A reduced loop pointer whose own defining store still uses the biv
  (`sw 0x3C($a3)` while its neighbours read `-0x34($t0)`): that store, and
  every other biv-based store beside it, is volatile.** Loop combines and
  counts volatile address givs but cannot rewrite them. (func_8002097C)
- **Volatile stores freeze memory order, so retail's interleaving of loads
  between them is source order**: a load sitting between two volatile
  groups was a separate statement there (`z = v >> shift;`). (func_8002097C)
