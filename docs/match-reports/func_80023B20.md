## Levers

- **The yaw in a local.** `ABS(sGame.unk380 - D_800A7680->vy)` with the
  member in every compare reloads the halfword at each test (long). Retail
  loads it once into `$a0`: `yaw = D_800A7680->vy;`.
- **An inline ternary abs, not an `if (d < 0) d = -d;` statement.** Both
  give the same `bgez`/`negu`, but with the statement (54/55) the first
  `beqz` of the 56-arm lands on the reload of 0x380; with `(d < 0 ? -d :
  d) > 56` it skips the reload (the value is still in `$v1` when the store
  was skipped), as retail does and as the 0x384 decay above it does. The
  `if` statement seems to end the stretch over which cc1 knows the loaded
  value is current; the ternary does not.
- Rejected on the way: swapping the arms (`d <= 56` first) moves the
  skip-reload to whichever arm is laid out first (49/55); a nested
  `if/else if` for the 56-arm and a local copy of 0x380 change the length.
- `u16` counter: `andi 0xFFFF` + `sltiu 3`, as the round-3 learning says.

## Struct

`GameState` gains `unk380` and `unk384` (both `s32`, replacing part of
`pad354`); the whole image stays OK.

### Proposed learning

When a branch arm that skips a store jumps PAST the reload of the stored
field (`beqz` to just after the `lw`), the value was still known from the
previous test; if the build reloads instead, look for an intervening `if`
statement (such as an abs written `if (d < 0) d = -d;`) and fold it into
an expression (`(d < 0 ? -d : d) > K`).
