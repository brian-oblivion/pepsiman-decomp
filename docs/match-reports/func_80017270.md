## The scratchpad stack switch (for the head to rule on)

Retail moves `$sp` to the scratchpad (`0x1F8003FC`, the old `$sp` saved
there, a 24-byte frame below it) around `GsSortObject4J`, and back after.
That has no C spelling. The macro is two **basic** `__asm__ volatile`
statements: no operands, no constraints, no clobber list, so nothing pins a
C value to a register (CLAUDE.md rule 7 is about that). The `li $t1` /
`move $t0, $t1` pair is copied as retail has it; the original macro
probably took the address as an `"r"` input, which would be an operand
constraint and is not used here. The same sequence appears in
func_80016D14 (main), func_8001819C (code_7d74) and func_8003A008
(code_29f54), so the macro is a candidate for a shared header; it is kept
in `src/main.c` until the head decides.
