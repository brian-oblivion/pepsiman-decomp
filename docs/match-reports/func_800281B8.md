## Levers

- **Operand order sets load order.** `g->unk3CC >= g->unk39C` loads 0x3CC
  first; retail loads 0x39C into `$v1` first, which `g->unk39C <=
  g->unk3CC` gives.
- **`D_8009EF44` is an array here although `lui` and `lw` share `$v1`.**
  Retail's `lui $v1,%hi` sits in the `bne` delay slot with an unrelated `lw`
  between it and `lw $v1,%lo($v1)`. As a scalar (`extern s32 D_8009EF44;`)
  the assembler emits the pair adjacent, the slot gets a `nop` and the
  function grows a word. `extern s32 D_8009EF44[];` lets cc1 schedule the
  `lui` itself: 42/42. Only this function references the symbol.
- The two `func_80042538(30)` calls are cross-jumped into one by the
  compiler; the `ret != 0` test after them stays separate.

## Evidence for retyping `D_800734AC`

Here it is passed as the table argument of `func_80015450(table, 6)`;
`func_80015450` (main) computes `table + (index & 0xFFFF) * 10` and reads
halfwords at +0, +2, +8 and bytes at +4, +5 of the record: an array of
10-byte records, the `TableHeader` main.c casts it to. A retype to that
record array would serve this call too (it needs only the address).

### Proposed learning

The "same register for `lui` and the load means a scalar" rule holds only
when the two are adjacent. A `lui` scheduled away from its load (into a
delay slot, with other instructions between) is cc1's split of an array,
even when it picks the load's destination register for the `%hi`.
