### Proposed learning

- A forward `beqz` whose slot retail fills from the fall-through, where
  the build steals the loop test's first insn from the target: the target
  label is right before `NOTE_INSN_LOOP_VTOP`, which reorg reads as "jump
  to the loop test, likely taken". A bare `__asm__("")` at the end of the
  loop body moves the label off the note. (func_8001819C)
- Block-copy scratch registers (`movstrsi` temporaries) follow which hard
  registers are ever live in the function, so an asm that hides its
  clobbers in the template shifts them. (func_8001819C)

## Round 13 (bravo)

Splice re-measured: 117/133, `insertions 3 / deletions 3`, the same 16
words (both copies' scratch registers). No C changed; this round read
why, in gcc 2.8.1's `reload1.c`, and the answer leaves no C spelling.

- The `movstrsi` temporaries are `match_scratch` operands, so reload
  allocates them from its spill registers. `order_regs_for_reload` lists
  first the registers no pseudo was allocated to and that no RTL names
  explicitly (`regs_explicitly_used`, the pre-reload `regs_ever_live`),
  in register-number order (MIPS has no `REG_ALLOC_ORDER`). The build's
  are `$8..$11`.
- `allocate_reload_reg` hands spill registers out round-robin from
  `last_spill_reg`, so each reload between the two copies rotates the
  restore's registers by one.
- Retail's `t1..t4` / `t2, t3, t4, t1` is exactly: `$8` named by the
  asm (its clobber), and one reload between the copies (the asm's `"r"`
  operand, `0x1F8003FC` reloaded into `t1`, the first spill register).
- Pure C cannot do either: `$8` is reached only by a pseudo allocated to
  it, which shows as a visible `$t0` somewhere retail has none, and any
  reload between the copies adds instructions. The lever that matched
  func_80017F0C this round (empty asm insns to reorder global-alloc) does
  not reach reload's spill order.

So the 16 words wait on the operator's `include/spad.h` decision above
(posted again on the round-13 broadcast). Builds this round: 1.

## Why it is skipped

Around the GsSortObject4J call retail moves `$sp` onto the scratchpad:

```
lui   $t1, 0x1F80 ; ori $t1, $t1, 0x03FC
move  $t0, $t1
sw    $sp, 0($t0)
addiu $t0, $t0, -0x18
move  $sp, $t0
...   jal GsSortObject4J
addiu $sp, $sp, 0x18
lw    $sp, 0($sp)
```

That is the shape of Psy-Q's SetSpadStack/ResetSpadStack sample
macros, which are inline asm with register operands. Hard rule 7 bans
extended-asm operand constraints outside `include/gte.h`, so there is no
allowed C spelling. The same sequence appears in `main` (func_80016D14,
func_80017270) and `code_29f54` (func_8003A008), so one sanctioned macro
in a header (as `include/gte.h` does for COP2) would unlock all four.
Posted to the broadcast for an operator decision.
