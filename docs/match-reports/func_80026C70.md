## Levers

- **A struct-of-array lvalue over the shared `s32 D_800DD070[]`.** Through
  a pointer (`GsF_LIGHT *l = (GsF_LIGHT *)D_800DD070;`) or a cast macro
  `((GsF_LIGHT *)D_800DD070)[i]`, cc1 keeps `&l[1]` and `&l[2]` in saved
  registers from the prologue and stores the second and third lights
  relative to them (frame 0x28, one extra saved register, long). Retail
  stores everything relative to the base and builds `base + 0x10` only for
  the call. A local experiment with `D_800DD070` declared as a struct
  array in common.h matched the structure (69/75); the unit-local
  `LightTable` wrapper `#define sLights (*(LightTable *)D_800DD070)` gives
  the same code with no shared-header change (the round-2 struct-lvalue
  lever, func_800285B0). common.h is unchanged.
- **Chained assignment stores right to left** (round-3 learning):
  `l[0].r = l[1].r = l[2].r = c[0]` stores light 2's byte first, as
  retail.
- **Index-first integer sum** (bravo's round-5 lever): retail adds `idx +
  ptr` (`addu v1, v1(idx), v0(ptr)` with the index loaded first).
  `D_80095790 + idx` and `&D_80095790[idx]` put the pointer first (69/75,
  register swap only); `(u8 *)(idx * 4 + (s32)D_80095790)` matches.
- The constant 100 stays in `$s1` across the three calls and serves the
  final compare with no local needed.

### Proposed learning

When a pointer or cast over an array-of-unknown-size global makes cc1
hoist `&tbl[k]` into saved registers (stores relative to them), wrap the

`(*(Table *)D).rec[k].f`; it keeps every access relative to one base.
