# func_800201BC — MATCHED (217/217), round 8, runner delta

Unit `src/code_a0bc.c`. The TMD handler for lit gouraud-textured triangles
in func_80020CF8's modes 0 and 1. Per visible TmdGT3 it writes TWO packets:
a POLY_FT3 (code 0x26, texture page 0x7B, CLUT 0x722D, coloured with light
0's colour) whose UVs are an environment map from the rotated normals (`u =
(nx >> 7) + 0x20`, `v = (ny >> 7) - 0x20`), then a POLY_GT3 (code 0x34)
over the same screen coordinates with the TMD's own UVs and colours from
`gte_ncct` on the three normals, both linked at the triangle's depth.

New in this round: the unit-local `FlatLights` view and `sLights` macro
(code_7d74's spelling) for `D_800DD070`, and an additive
`gte_strgb3_gt3(r1)` in `include/gte.h` (Sony's one-pointer store of RGB0-2
at +0x4, +0x10, +0x1C). The local prototype changed from `PACKET
*func_800201BC();` to the full one.

```c
PACKET *func_800201BC(TmdGT3 *prim, SVECTOR *vtx, SVECTOR *nrm, PACKET *packet, s32 n, s32 shift,
                      GsOT *ot) {
    /* MATCHING: a volatile copy of the parameter, so the triangle's fields
     * stay on it and only the second packet goes through loop's pointer. */
    volatile POLY_FT3 *pkt;
    VECTOR mac;
    CVECTOR c;
    s32 v;
    POLY_GT3 *g;
    s32 i;
    u32 *tag;

    pkt = (POLY_FT3 *)packet;
    for (i = 0; i < n; i++, prim++) {
        gte_ldv3(&vtx[prim->v0], &vtx[prim->v1], &vtx[prim->v2]);
        gte_rtpt();
        gte_stflg(&v);
        if (v & 0x7F85E000) {
            continue;
        }
        gte_nclip();
        gte_stopz(&v);
        if (v <= 0) {
            continue;
        }
        gte_avsz3();
        gte_stotz(&v);
        gte_stsxy3_ft3(pkt);
        pkt->r0 = sLights[0].r;
        pkt->g0 = sLights[0].g;
        pkt->b0 = sLights[0].b;
        pkt->code = 0x26;
        pkt->tpage = 0x7B;
        pkt->clut = 0x722D;
        gte_ldv0(&nrm[prim->n0]);
        gte_rtv0();
        gte_stlvnl(&mac);
        pkt->u0 = (mac.vx >> 7) + 0x20;
        pkt->v0 = (mac.vy >> 7) - 0x20;
        gte_ldv0(&nrm[prim->n1]);
        gte_rtv0();
        gte_stlvnl(&mac);
        pkt->u1 = (mac.vx >> 7) + 0x20;
        pkt->v1 = (mac.vy >> 7) - 0x20;
        gte_ldv0(&nrm[prim->n2]);
        gte_rtv0();
        gte_stlvnl(&mac);
        pkt->u2 = (mac.vx >> 7) + 0x20;
        pkt->v2 = (mac.vy >> 7) - 0x20;
        g = (POLY_GT3 *)(pkt + 1);
        tag = (u32 *)ot->org + (v >> shift);
        *(u32 *)pkt = (*tag & 0xFFFFFF) | 0x07000000;
        *tag = (u32)pkt & 0xFFFFFF;
        c.r = c.g = c.b = 0x80;
        gte_ldrgb(&c);
        gte_ldv3(&nrm[prim->n0], &nrm[prim->n1], &nrm[prim->n2]);
        gte_ncct();
        *(u32 *)&g->u0 = prim->uv0;
        *(u32 *)&g->u1 = prim->uv1;
        *(u16 *)&g->u2 = prim->uv2;
        *(u32 *)&g->x0 = *(u32 *)&pkt->x0;
        *(u32 *)&g->x1 = *(u32 *)&pkt->x1;
        *(u32 *)&g->x2 = *(u32 *)&pkt->x2;
        tag = (u32 *)ot->org + (v >> shift);
        *(u32 *)g = (*tag & 0xFFFFFF) | 0x09000000;
        *tag = (u32)g & 0xFFFFFF;
        gte_strgb3_gt3(g);
        /* MATCHING: a volatile store, which loop cannot rebase onto its
         * reduced pointer. */
        ((volatile POLY_GT3 *)g)->code = 0x34;
        pkt = (POLY_FT3 *)(g + 1);
    }
    return (PACKET *)pkt;
}
```

## How it went

1. First body (packet as a plain parameter, `gte_strgb3` with three member
   addresses): 11/217, loop made `$a3` the reduced pointer and copied the
   packet to `$t0`.
2. A volatile local copy of the packet (func_8001FBBC's shape): `$a3`
   stays the triangle's base and `$t1 = $a3 + 0x27` becomes the second
   packet's reduced pointer, as retail.
3. `gte_strgb3_gt3(g)`: retail stores the GT3 colours from one base. With
   three member addresses cc1 folds them onto the packet base and `g` dies.
4. `((volatile POLY_GT3 *)g)->code = 0x34;`: retail's last store goes
   through `g` (`$a2`), not the reduced pointer.
5. The GT3 field copies: UV words first, then the coordinates in x0, x1,
   x2 order. The `*(u32 *)&pkt->xN` reads drop the volatile, so they
   schedule freely; this order makes the uv2 temporary take `$a1`, `g`
   take `$a2`, `nrm` move to `$t5` and `n`/`shift` take `$s1`/`$s0`, all as
   retail. 217/217.

### Proposed learning

- A colour triple stored `swc2 $20/$21/$22` at 4/0x10/0x1C from ONE base
  register: `gte_strgb3_gt3(p)` (now in include/gte.h). Three member
  addresses fold onto another base.
- In a loop with two packets per pass, a whole cascade of register choices
  (which parameter is copied out, how many saved registers) can hang on the
  source order of a few independent word copies; try the store orders before
  anything structural.
