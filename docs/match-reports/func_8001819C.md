# func_8001819C — SKIPPED: needs a scratchpad-stack macro the rules do not allow (not attempted in C)

Unit `src/code_7d74.c`, left as `INCLUDE_ASM`. Round 7, runner alpha.

Draws every live slot of the slot list at `D_800D8360` (skipping
when the game state's byte 2 is clear and `D_8009585C & 3` and its mode
byte say so): for each slot with a key and an object it saves the
16-byte slot on the stack, sets the GTE's local-screen and light
matrices from the object's coordinate system (GsGetLs/GsSetLsMatrix,
GsGetLw/GsSetLightMatrix), sorts the object with GsSortObject4J into
`D_800ACEA8[D_80095750]` or `D_800A7318[D_80095750]` (by the game
state's halfword at 0x3CA) with the scratchpad at 0x1F800000 as its
packet area, and copies the saved slot back.

## Why it is skipped

Around the GsSortObject4J call retail moves `$sp` onto the scratchpad:

```
lui   $t1, 0x1F80 ; ori $t1, $t1, 0x03FC
move  $t0, $t1
sw    $sp, 0($t0)
addiu $t0, $t0, -0x18
move  $sp, $t0
...   jal GsSortObject4J
addiu $sp, $sp, 0x18
lw    $sp, 0($sp)
```

That is the shape of Psy-Q's SetSpadStack/ResetSpadStack sample
macros, which are inline asm with register operands. Hard rule 7 bans
extended-asm operand constraints outside `include/gte.h`, so there is no
allowed C spelling. The same sequence appears in `main` (func_80016D14,
func_80017270) and `code_29f54` (func_8003A008), so one sanctioned macro
in a header (as `include/gte.h` does for COP2) would unlock all four.
Posted to the broadcast for an operator decision.
