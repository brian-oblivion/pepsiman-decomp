### The `andi` (length): a volatile empty asm

combine deletes port 1's `andi 0xFFFF` because `nonzero_bits` of the
`xor` of two shifted bytes is 0xFFFF. A bare `__asm__("")` between the xor
and the `(u16)` does NOT stop it: basic asm is `ASM_INPUT`, and
`volatile_insn_p` returns 0 for it, so `can_combine_p` combines across.
`__asm__ __volatile__("" : : )` is `ASM_OPERANDS` with the volatile bit;
`can_combine_p` rejects any volatile insn between i2 and i3, so the andi
survives and the length is exact. It has no operands and pins no register,
but it is the extended syntax: **the head must rule whether hard rule 7
allows it** (posted on the broadcast). It is also a sched barrier.

### Levers, in order (each from the best body of its moment)

| Change | Score |
| --- | --- |
| volatile asm replaced by `if (btn >> 16) btn = 0;` after port 1's xor | 101, length exact, no asm |
| port 0's narrowed buttons in a NEW local, `b = (u16)btn;`, used for the stores and the `and` | 112 |
| port 0's buttons built up over three statements, `btn = D[k + 2] << 8; btn \|= D[k + 3]; btn ^= 0xFFFF;` | 115 |
| the same for port 1 | 118, MATCHED |
| `if (btn >> 16)` removed again (the split statements keep the `andi` on their own) | 118 |

Why each works:

- `if (btn >> 16) btn = 0;`: cse cannot fold the test, so the label splits
  the block before combine, and combine never gets the xor and the
  `(u16)` together. combine then folds the test through nonzero_bits and
  jump2 deletes the dead arm, which leaves no code. It is the first lever
  that kept the `andi` without asm; the final source doesn't need it.
- `b = (u16)btn;`: `b` is a block-local pseudo, so local-alloc gives it
  `$v1` ahead of the D_80095854 load, which goes to `$a0`. With `$a0`
  free over port 0's stores, sched2 hoists the load to where retail has it.
  No multi-set `m1` is needed, so the global-alloc fight between `m1` and
  the D_80072F44 base (round 13's 90 variant) never happens.
- The three-statement buttons: the hi byte's address is the first add and
  the lo byte's is the copy, with idx/copy in `$v0` and the hi chain in
  `$v1` as retail has them. Of the one-expression spellings, lo-first gets
  the registers right with the loads swapped and hi-first swaps every
  register. Built up in one local, the xor's operand is `btn` itself, and
  combine keeps port 1's `andi`.

- `t` reused for the port-1 index (`t = D_80072F44[1];`), making it

- Hi first in one expression for both ports: 81.

### Proposed learning

- **A redundant `andi 0xFFFF` after `xori 0xFFFF` on two shifted bytes:
  build the value up in one local over several statements** (`v = hi <<
  8; v |= lo; v ^= 0xFFFF;`). Written as one expression, combine sees the
  xor's operand is 16 bits and drops the mask. The same split also decides
  which byte load gets which address register. (func_80014FA8)
- **A mask that combine deletes can be kept with no code: a test that cse
  cannot fold but combine can** (`if (v >> 16) v = 0;` on a value known to
  be 16 bits). The label splits the block before combine, and jump2 deletes
  the dead arm. (func_80014FA8, round 14; not needed in the final source)
- **A narrowed value reused in a block: put it in a new local** (`b =
  (u16)btn;`, not `btn = (u16)btn;`). The block-local pseudo goes through
  local-alloc first and takes `$v1`, which moves a neighbouring load to
  another register. (func_80014FA8)
